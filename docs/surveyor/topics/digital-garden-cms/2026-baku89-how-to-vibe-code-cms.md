## 先行研究と比べてどこがすごいの？

- 一般的な CMS（WordPress のカスタム投稿タイプなど）が前提にする「投稿の種類ごとにスキーマを分ける」「分類を専用の概念として持つ」「フォルダで整理する」を、どれも採らないよう勧めている。
- 教訓が短い命令形の箇条書きなので、AI エージェントに設計方針として渡しやすい。

## 技術や手法の"キモ"はどこにある？

1. **ページ本文とメタデータを単一のスキーマに統一する**: 日記、作品、CV のような固定ページまで包摂できる汎用スキーマを用意し、カスタム投稿タイプを作らない。
2. **タグやカテゴリをただのページとして扱う**: 「ページ A からページ B にリンクがある」ことを「A は B というカテゴリに属する」と解釈する。カテゴリやタグは、`categories` や `tags` のメタデータにページの URL を入れる特殊なリンクとして扱う。
3. **プレーンテキストの軽量マークアップ言語を唯一のソースにする**: Markdown などを使い、必ず HTML を直接書けるようにする（React なら MDX、Vue なら MDC）。Obsidian の vault をそのままソースにすれば、エディタを自作せずに済む。LLM との相性もよい。
4. **フォルダ整理をしない**: 階層性と線形性を信じない、という設計思想に従う。
5. **trailing slash の有無を区別する**: `xxx.md` を `example.com/xxx` に、`xxx/index.md` を `example.com/xxx/` に対応させる。ディレクトリごとに git submodule を分けたいときに役立つ。

## 議論はあるか？

- 教訓 3 の「HTML を直接書けるようにする」は、作者の別ページ（設計思想）にある「愚行権を認める」と同じ方針で、表現の自由度と引き換えに、サニタイズや表示崩れへの対処を CMS の外に出す判断である。
- 教訓 4（フォルダ整理をしない）と教訓 5（trailing slash でディレクトリを区別する）は一見矛盾する。教訓 5 はフォルダを分類ではなく、URL 空間やリポジトリの分割単位として使う場面を想定しているとみられる。
