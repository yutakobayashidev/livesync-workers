## どんなもの？

- 個人 Web サイトの形式とその思想として「Hyperstrata（ハイパーストラタ）」を提案する記事である。各ノートをその時点の思考の層として保存し、後から書いたノートから引用リンクで参照することで、思考の堆積と変遷をネットワーク状の地層として残す。
- フレームワークやライブラリの名前ではなく、サイトの形式の名前である。
- 前提として、同日公開の「デジタルガーデンについて思うこと」でデジタルガーデンを評価している。デジタルガーデンの特徴を、未完成のメモを公開する、時系列で並べない、継続的に成長し続ける、個人が所有権を持つ、の 4 点に整理し、庭を public と private の中間領域とみる考え方を支持している。

## 先行研究と比べてどこがすごいの？

- デジタルガーデンの弱点として維持管理の負担を指摘する。未完成の記事を公開してよいことで最初に書くハードルは下がるが、その後も手入れし続ける必要があり、手入れを続けられない人の庭は放置された記事で荒れる。一方ブログは、一度書いた記事の手入れは少ないが、自己完結した記事を書くハードルが高い。
- Hyperstrata はこの両者の間を狙う。記事を書き捨てられる気軽さを保ちつつ、書いた記事は原則として書き換えないので、維持管理の負担が増えない。
- デジタルガーデンが時系列を嫌いすぎているという批判も含む。単一のタイムラインが問題なら、網状流のように分岐して合流する複数の流れとして時系列を残せばよい、という立場である。

## 技術や手法の"キモ"はどこにある？

- **引用ネットワーク**: Markdown の中に `^[[slug]]` と書くと、その記事を引用できる。引用はビルド時に収集され、各記事の末尾に References と Cited By のセクションが自動で付く。グラフは原則として過去の記事を参照する DAG になるが、相互引用によるループも許容している。
- **なるべく不変にする**: typo や言い回しの修正は上書きしてよいが、内容を改訂するときは古い記事を引用した新しい記事を書く。訂正された記事の Cited By に訂正記事が現れるので、古い記事から訂正の履歴を辿れる。
- **記事は自己完結しなくてよい**: 書きかけを投稿し、続きを新しい記事として積んでよい。記事は単体ではなく、引用ネットワークの中の位置とともに読まれる。

## どうやって有効だと検証した？

- 作者自身のサイトが Hyperstrata として運用されており、左側に記事と引用リンクのグラフを描画している。作者は、以前書いた記事の訂正を別記事にして引用でつないだ実例を挙げている。定量的な評価はない。

## 議論はあるか？

- 続編の記事で、作者自身が「Hyperstrata には引用ネットワークが必須ではないかもしれない」と論点を更新している（今回は表題のみ確認）。重要なのは層とネットワークであり、そのネットワークが引用でできているかどうかは本質ではない、という主張である。
- 記事を不変に保つ規律は書き手に委ねられており、仕組みで強制するものではない。
