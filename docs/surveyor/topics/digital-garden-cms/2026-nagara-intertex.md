# Intertex

https://aratanagara.com/intertex/

- 永良 新（個人）

## どんなもの？

- アウトライン、マップ、テーブルの三つの画面で一つの木構造を表示し、どの画面からでも編集できる「メタテキストエディタ」である。ブラウザで動き、PWA としてオフラインでも編集できる。
- 作者が連載中の作品の設定資料を Dynalist で管理していて、Google Docs 側の設定と突き合わせる作業に限界を感じたことが直接のきっかけである。

## 先行研究と比べてどこがすごいの？

- Workflowy や Dynalist のようなアウトライナーは、木の別々の枝が互いを参照する関係（一話の伏線が七話の設定につながる、など）をうまく書けない。Intertex は、木を越えてノード同士をつなぐリンクを一級市民として扱う。
- 設計中に baku89 から聞いた「ユーザーごとに巨大なアウトラインを一つだけ作り、考えたい枝にズームすればいい」という考えが効いている、と作者は書いている。

## 技術や手法の"キモ"はどこにある？

- 最小単位は段落である。段落は本文のほかに、一段小さいメタテキスト、キーと値のメタ情報、色、マップ上の座標を持つ。
- タグ専用の入力欄はなく、本文中の `#` を自動で拾う。タグについては本文が唯一の正とする。
- 三つの画面は役割が違う。アウトラインは書いて構造を作る場所、マップは関係を俯瞰してノードをつなぐ場所、テーブルは同じラベルの項目が並ぶ枝を表にして比べながら書き換える場所である。
- データはブラウザに保存し、文書ごとに JSON と Markdown で書き出せる。Google ドライブにつなぐと Markdown として自動保存し、ドライブ側の変更を段落単位で取り込む。横断リンクは Obsidian のブロック識別子に対応させている。
- 共有は URL を発行して文書単位で同期する。閲覧用と編集用のリンクを分けられる。サーバーは自作の PHP 1 枚と JSON ファイルだけである。
- ビルドもフレームワークも使わず、HTML、CSS、JS 各 1 ファイルで書いている。作者は、道具にとって最も怖いのは機能不足ではなく数年後に開けなくなることだと述べている。

## どうやって有効だと検証した？

- 作者自身の設定資料を Dynalist から移行し、使い続けている。定量的な評価はない。

## 議論はあるか？

- 日本語で書くための道具として IME 対応を最優先にしている。変換確定の Enter で段落が割れないようにし、編集中の行はタグなどの装飾を外してプレーンテキストに戻す。表示の豊かさよりキャレットと変換の安定を優先した割り切りである。
- AI はツールを作るところまでに使い、中に書く文章には一切関わらせていない、と作者は明記している。
