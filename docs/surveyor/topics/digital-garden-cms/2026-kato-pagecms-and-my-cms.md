# PX激変期、ブログを編集しやすくした

People are Programmers（ブログ記事）, 2026-09-28

https://blog.junkato.jp/ja/posts/2026-09-28-pagecms-and-my-cms/

- 加藤 淳（個人ブログ）

## どんなもの？

- Markdown で管理しているブログに、Cloudflare Workers 上で動く編集画面を自作した経緯の記録である。AI エージェントを延べ 1 時間ほど走らせただけで完成したと書いている。
- 作者は baku89 のようにデジタルガーデンを作り込む方向も検討したうえで、既存のブログを編集しやすくする方向を選んだ。

## 先行研究と比べてどこがすごいの？

- 先に Pages CMS を試している。Pages CMS は設定ファイル 1 枚を置けば、GitHub App の仕組みでリポジトリ内の Markdown を読み、編集画面を出してくれる。導入コストがほぼゼロで、多くの場合はこれで十分だと評価している。
- 一方で、iPad Pro では組み込みの WYSIWYG エディタが重いこと、生の Markdown を編集するモードにプレビューがないことが不満だった。作者のブログは `<figure>` タグで画像の並べ方を細かく指定しており、その確認にプレビューが欠かせない。この細部の不満を解消するために自作した。

## 技術や手法の"キモ"はどこにある？

- GitHub 上の Markdown と画像を fine-grained token で読み書きし、その token を持たせた編集用 Web アプリを Cloudflare Workers でホストする。
- 認証は Cloudflare One の無料枠で、GitHub OAuth かメールのワンタイムトークンを使う。
- 毎回 GitHub から全部取得するのは重いので、IndexedDB にキャッシュする。アップロード前の記事や画像の一時保管にも IndexedDB を使う。
- 既存記事の画像レイアウトを AI に解釈させ、専用の編集 UI として抽象化させた。

## どうやって有効だと検証した？

- 作者自身のブログで運用している。従来なら調べものを含めて一週間かかった実装量が、週末だけでできたと書いている。

## 議論はあるか？

- 作者は、ここまで速く作れたのは、編集対象の Markdown の仕様（frontmatter によるタグと下書き管理、画像レイアウトの書き方）が既に固まっていたからだと分析している。データ構造が決まっていれば、それを扱うコードは AI がすぐ書ける。
- 一から AI に頼むと、確認すべき点が多すぎて開発者の mental workload が限界を超える。開発者がしっかりした価値観と判断基準を持ち、AI をそれに沿わせる技術が重要になる、というのが作者の結論である。
